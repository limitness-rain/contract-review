# 二轮合同复核

## 开场

每次用户显式调用本 Skill，或本对话首次自动识别为合同复核任务时，在取件或处理文件前先发一条简短的用户可见消息。若当前请求已按项目指引发过这条提示，直接继续：

> 可以直接说「复核保管合同」，发实习生交接 ZIP 做律师复核，或发律师终版 ZIP 做验收并导出 Excel。三个阶段都用现有的「合同复核工具.html」。

用户已给出任务或材料时，发完后直接继续。只说「用这个 Skill」「怎么用」或只调用 `$contract-review` 时，给出开场提示即可，等用户给合同类型或 ZIP。连续办理同一批次时，普通追问无需重复开场。

## 识别用户要办的事

- **收到 ZIP，或用户指向当前对话已有的 ZIP。** 优先使用它。接受「同学包」「实习生交接」「律师待审」「律师最终稿」「帮我打开这个包」「验收一下」「出表」等说法。先用 `receive --zip <文件> --out <新目录>` 核验，阶段以包内清单为准，文件名和说法只提供线索。只有用户明确指定的操作与核验阶段冲突时，说明差异并核实要处理哪个包。对话中有多个可能的包且无法定位时，只问要用哪一个。
- **只有合同类型，或合同类型加「生成 HTML」「做个复核页面」「发我能打开的文件」。** 在本 Skill 或复核项目中按该类型取件，进入复核流程。例如「帮我生成商标许可使用合同的 HTML 文件」按「商标许可使用合同」取件。保留用户输入的类型，用计划表中的正式类型消歧。确有多个候选时，列出候选请用户选；材料不足时说明缺项。
- **只要求打开已有工具或导入。** 指向固定工具；已有 ZIP 就核验后按阶段导入。需要批次数据而对话中没有类型或 ZIP 时，只问缺少的那项。
- **明确要求起草合同正文、做可填写合同模板或另做网站。** 说明本 Skill 的交付范围是合同标注复核。若用户指的是复核入口，按上面的类型或 ZIP 继续。

## 执行对应流程

按[工作流与命令](references/Codex工作流.md)处理当前阶段。运行 `scripts/review_workflow.py`，把 ZIP、Excel 和报告写入用户可用的目录。

**页面只使用随 Skill 提供的 [合同复核工具.html](assets/合同复核工具.html)。** 返回命令给出的固定工具和本批 ZIP 的绝对本地链接。批次处理中禁止自行写代码、调用构建命令或网页生成工具来新建、复制、修改 HTML 或嵌入 ZIP，包括可填写合同网页。固定工具缺失时，说明缺项并提示恢复原文件或重装 Skill。用户可在固定工具点「导入已有 ZIP」和「选择 ZIP」。需要代导入时，用本机浏览器在同一工具选择该 ZIP，确认阶段后交由用户填写署名或进入；浏览器不可用时提供手动导入步骤。

- **用户给出合同类型。** 用本机已授权的 `lark-cli` 用户身份运行 `collect`，检查退出码和 `取件/取件结果.json`。取件失败时说明合同类型、初标状态、缺失或无法读取的标注集、附件及需补材料，报告有文件名时照列。材料齐备后逐份核对评测 Word 和有效附件，记录类型及版本依据，再运行 `prepare`。类型不符时列出文件并暂停该批。
- **收到复核 ZIP。** 用 `receive` 校验清单并确认阶段。实习生或律师在固定工具中导入对应 ZIP。律师终版在同一工具只读验收，同时输出预检报告和可用的本地 Excel。按[标注与导出](references/标注与导出.md)完成四项检查，以实际材料记录核验依据。
- **终版交付。** 先给固定工具和终版 ZIP 的独立链接。询问是否写入飞书，缺少明确目标或操作时一并确认。取得用户同意后，使用同一终版 ZIP、Excel 和状态为 `ready` 的预检报告运行 `publish`，交付 Excel、目标表链接和回读回执。写入状态不明时先核对远端。 来源表仅用于取件。
