# 二轮合同复核

## 开场

每次用户显式调用本 Skill，或本对话首次自动识别为合同复核任务时，在取件或处理文件前先发一条简短的用户可见消息。若当前请求已按项目指引发过这条提示，直接继续：

> 可以直接说「复核保管合同」，发实习生交接 ZIP 做律师复核，或发律师终版 ZIP 做验收并导出 Excel。三个阶段都用现有的「合同复核工具.html」。

用户已给出任务或材料时，发完后直接继续。只说「用这个 Skill」「怎么用」或只调用 `$contract-review` 时，给出开场提示即可，等用户给合同类型或 ZIP。连续办理同一批次时，普通追问无需重复开场。

## 识别用户要办的事

- **上传文件夹、合同 Word 或标注 Excel 准备建包。** 即使用户同时报了合同类型，也先问「这次是否只用你上传的材料生成初始包，跳过飞书取件？」等用户确认。用户已经明确选择来源时按其选择。有多批材料，或同时提供了源材料和交接 ZIP 且用途不清时，一起确认本次用哪些。确认用本地材料后进入本地建包流程。明确选择飞书后再取件。
- **收到复核数据 ZIP，或用户指向当前对话已有的复核数据 ZIP。** 接受「同学包」「实习生交接」「律师待审」「律师最终稿」「帮我打开这个包」「验收一下」「出表」等说法。用 `receive --zip <文件>` 核验包及保存时的阶段。两种身份均可在网页中打开同一个包继续复核，也可以直接导出当前标注集。历史 `final` 阶段包加 `--out <新目录>` 输出验收材料，可按原包再次运行。对话中有多个可能的包且无法定位时，只问要用哪一个。
- **只有合同类型，或合同类型加「生成 HTML」「做个复核页面」「发我能打开的文件」。** 在本 Skill 或复核项目中按该类型取件，进入复核流程。例如「帮我生成商标许可使用合同的 HTML 文件」按「商标许可使用合同」取件。保留用户输入的类型，用计划表中的正式类型消歧。确有多个候选时，列出候选请用户选；材料不足时说明缺项。
- **明确要求给某类合同预埋风险。** 先用 `collect` 核对初标和评测材料，再按预埋流程办理。已有评测 Word 的未初标批次默认沿用现有版本。用户明确要求补预埋时，保留原评测附件并核对补样范围。
- **只要求打开已有工具或导入。** 指向固定工具；已有 ZIP 就核验后按阶段导入。需要批次数据而对话中没有类型或 ZIP 时，只问缺少的那项。
- **明确要求起草合同正文、做可填写合同模板或另做网站。** 说明本 Skill 的交付范围是合同标注复核。若用户指的是复核入口，按上面的类型或 ZIP 继续。

## 执行对应流程

按[工作流与命令](references/Codex工作流.md)处理当前阶段。运行 `scripts/review_workflow.py`，把 ZIP、Excel 和报告写入用户可用的目录。

**页面只使用随 Skill 提供的 [合同复核工具.html](assets/合同复核工具.html)。** 返回命令给出的固定工具和本批 ZIP 的绝对本地链接。批次处理中禁止自行写代码、调用构建命令或网页生成工具来新建、复制、修改 HTML 或嵌入 ZIP，包括可填写合同网页。固定工具缺失时，说明缺项并提示恢复原文件或重装 Skill。用户可在固定工具点「导入已有 ZIP」和「选择 ZIP」。需要代导入时，用本机浏览器在同一工具选择该 ZIP，确认阶段后交由用户填写署名或进入；浏览器不可用时提供手动导入步骤。

- **已确认采用本地材料。** 按[本地材料工作流](references/Codex工作流.md#用上传的本地材料生成初始-zip)运行 `local-inputs` 清点指定文件夹或文件。核对类型、标注引用的 Word 版本、正文与证据，再用 `prepare --local-inputs` 生成并用 `receive --stage student` 核验初始 ZIP。全程使用本地来源，材料缺失或冲突时说明如何补齐。核验后交付固定工具和初始 ZIP 的独立链接。
- **用户选择飞书，或只给合同类型、未上传建包材料。** 用本机已授权的 `lark-cli` 用户身份运行 `collect`，检查 `取件/取件结果.json`。`needs_annotation` 时列出评测附件并请用户完成初标、挂标注集；`needs_confirmation` 时列出原始样本并询问是否开始双立场预埋；`failed` 时报告「取件失败」、类型、初标状态、缺项和补充方式；`ready` 时逐份核对评测 Word 及有效附件，记录类型与版本依据后再运行 `prepare`。
- **已确认开始预埋。** 按[工作流](references/Codex工作流.md)运行 `risk-inputs --confirm`，读取计划表 v07 双方正式规则和[预埋提示词](references/风险预埋提示词.md)。按规则和正式审查立场盘点正例、负例、不适用及待核，以每组合至少 6 份不同合同的正例为目标补样。每份样本交两立场 Word 和逐件报告，有效翻转记录四项判断，其余按各立场预埋或原样复用。完成合同类型覆盖总表，用 `risk-review` 核验 Word 与逐件报告并生成待审清单。一并交由用户审阅，请用户明确同意将评测 Word 写入指定记录及字段。确认后才运行 `risk-upload --confirm`，保留已有附件并回读核验。
- **收到复核 ZIP。** 用 `receive` 校验清单。用户在固定工具中导入 ZIP 后选择身份，点击「导出当前进度 ZIP」保存或交接，点击「导出标注集 Excel」查看当前结果。历史 `final` 阶段包仍可用命令行输出预检和 Excel。按[标注与导出](references/标注与导出.md)完成四项检查，以实际材料记录核验依据。
- **终版交付。** 先给固定工具和终版 ZIP 的独立链接。询问是否写入飞书，缺少明确目标或操作时一并确认。取得用户同意后，使用同一终版 ZIP、Excel 和状态为 `ready` 的预检报告运行 `publish`，交付 Excel、目标表链接和回读回执。写入状态不明时先核对远端。
